Implement a real “Monthly Close” workflow per property: draft report -> review approvals -> publish.

Prisma:
1) Add enum ReportStatus: DRAFT, IN_REVIEW, PUBLISHED

2) Update or create ServicingReportRun model:
- id cuid
- propertyId FK
- periodStart DateTime
- periodEnd DateTime
- status ReportStatus @default(DRAFT)
- draftText String?
- publishedAt DateTime?
- createdAt, updatedAt

3) Add model ReportApproval:
- id cuid
- reportRunId FK ServicingReportRun
- role ApprovalRole (OPS/ACCOUNTING/COMPLIANCE)
- status String @default("PENDING") (PENDING|APPROVED|REJECTED)
- approvedByUserId String?
- notes String?
- createdAt, updatedAt

Backend routes (mount /api/servicing if not already):
- POST /api/servicing/property/:propertyId/monthly-close/start
- creates report run for current month (or given period)
- seeds ReportApproval tasks
- generates draftText using KPIs + template/LLM if configured
- POST /api/servicing/report-run/:id/submit -> status IN_REVIEW
- POST /api/servicing/report-run/:id/approve/:approvalId (admin)
- POST /api/servicing/report-run/:id/publish (admin)
- only if all approvals approved

UI:
- Extend your existing post-tokenization property management dashboard page (admin/tokenizer post dashboard) with a “Monthly Close” section:
- Start close, view draft, submit, approvals checklist, publish
- Demo mode: deterministic drafts + approvals.

Audit:
- Write audit events for start/submit/approve/publish if AuditEvent exists.
